# Search actions and access

> 中文译本：如与英文原文 [search-actions-and-access.md](search-actions-and-access.md) 有出入，以原文为准。

状态：`3.21.0-mf` 的现行参考文档。根据当前的理解缺口来选择动作。这是路由辅助，不是强制工作流，也不是后端排名。

## 选择下一步动作

| 缺什么 | 有用的首选动作 | 何时改变路线 |
|---|---|---|
| 某个术语或区分不清楚 | 定义、相邻概念与代表性示例 | 不同含义会导向不同的决策或用户目标；那就把各选项摆出来再提问 |
| 方法或候选范围未知 | 做一次小规模探索性检索，先形成临时地图 | 某个类别对决策重要时；此时应考察代表性候选，而不是一味收集名称 |
| 已知某个对象、版本或论断 | 有针对性地查官方资料、代码、案例或规范 | 找到目标；读原文并停止大范围发现 |
| 候选清单没有覆盖用户的输入/输出需求 | 对照真实使用场景检查覆盖度 | 缺失的能力会影响选择；直接针对该能力进行检索 |
| 结果为空或跑题 | 检查措辞、同义词、日期、域名与来源范围；必要时做一次小幅、有边界的改写 | 同一路线持续为空或开始返回另一个主题；记录该缺口 |
| 某条引用、视频、issue 或项目相关 | 有选择地沿来源或所引原文追溯 | 来源并不支持该论断；降低其权重，或沿下一个相关链接追溯 |
| 未知的只是本地效果 | 设计或运行一个获得授权的本地实验 | 没有授权、环境或安全的测试条件；交付验证方案即可 |
| 决策已有足够支撑 | 停止检索，直接作答 | 剩余未知项可能改变决策或其安全边界 |

当多个动作针对不同缺口时，可以组合使用。它们不会仅仅因为问题被标记为 comparison、latest 或 deep 就成为必做项。

## smart-search 的 hint

该封装接受如下 hint：

| Hint | 检索意图 |
|---|---|
| `quick` | 常规网页发现 |
| `official` | 优先发现官方或一手域名 |
| `deep` | 由已配置的深度研究后端给出综合 |
| `realtime` | 优先获取最新的网页/新闻内容 |
| `community` | 寻找社区讨论或 Reddit 内容 |
| `social` | 可用时寻找 X/Twitter 内容 |
| `scrape` | 抓取已知 URL |
| `video` | 查找视频内容，必要时获取文字稿 |
| `serp` | 搜索需求或 SERP 数据 |

多个 hint 组合表示多种检索意图。hint 并不保证拿到官方来源、社区覆盖、最新结果、页面访问权限或某个特定 provider。降级后的响应只是一条证据角色已改变的线索；它不能悄然变成强时效性或社交类论断的依据。

只有在适配器可用且动作有正当理由时，才使用直接适配器。`grok_search.mjs` 支持 `--web` 与 `--x`；`research.mjs` 调用 Tavily research 端点；其他第三方 CLI 需要 [operations.md](operations.md) 中所述的凭据 shim。不要把固定的工具矩阵当成研究发现写进报告。

## 本地优先与来源阅读

对于涉及“我们”的代码、配置、产品、历史或当前状态的问题，先读相关的本地文件与修订版本。本地路径、测试或运行时结果就能回答一个范围很窄的实现问题，无需外部检索。如果确实还需要外部上下文，要说明它用于填补哪个本地缺口。

对于网络来源，请把“发现”与“阅读”分开：

1. 先确定该页面可能支撑什么论断。
2. 按该论断所需的深度获取页面、文字稿、issue 或来源。
3. 检查实际正文或相关段落，而不只是标题、摘要片段、URL 或生成的总结。
4. 记录定位信息、版本/日期、访问状态，以及任何被省略的上下文。

当视频中的讲话、屏幕操作或其所引来源本身就是证据时，才使用该视频；不要强行把每个视频塞进固定类别。GitHub 依论断需要用于代码、发布、issue、pull request、设计讨论与运行证据。只有当用户的问题关乎搜索需求、触达面或市场信号时，才使用 SEO 或热度数据。

## 访问失败与有界恢复

明确说出观察到的失败类型：

- `403`/需要权限或登录；
- `429`/被限流；
- 正文只能由 JavaScript 渲染，或依赖浏览器；
- 正文被截断，或只有摘要；
- URL 格式错误/不安全；
- 主题不匹配；
- provider 报错或降级回退；
- 内容获取成功但并不支持该论断。

选择针对该失败的恢复手段：对已知 URL 使用已获准的提取器、一手镜像、文字稿、来源级引用、更窄的查询，或换一个 provider。目的不变地重复同一请求，只会消耗预算而不会改善证据。一次读取失败并不授权你去做无关的发现。

如果一次小规模恢复值得做，请记录原始失败与改变后的动作。如果不值得做，或共享预算已偏低，就把该来源标记为未读/部分读取，并用实际可用的证据继续。除非确实读过且内容支持该表述，否则绝不要把摘要片段、摘要、回退结果或检索结果描述成完整页面。
